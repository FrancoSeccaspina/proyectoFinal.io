# [1.1] Limpiar .gitignore del repositorio

**Fecha:** 2026-02-18

## Resumen

Se corrigió el `.gitignore` raíz del repositorio para excluir archivos que no deben formar parte del historial de git: variables de entorno con credenciales y artefactos de compilación generados automáticamente. Además, se eliminó del tracking de git todos los archivos que ya estaban commiteados por error.

## Cambios Principales

- Agregadas entradas en `.gitignore` para ignorar archivos `.env` en cualquier directorio del proyecto
- Agregadas entradas para ignorar `flask/app/static/` (build de React) y `frontend/build/`
- Eliminados del tracking (sin borrar del disco): `.env`, `Backend/.env`, `frontend/.env`
- Eliminados del tracking los 15 archivos del build de React en `flask/app/static/`

## Flujo de Trabajo

```
[git rm --cached] → archivos dejan de estar en git → permanecen en disco
[.gitignore actualizado] → git ignora esos paths en commits futuros
```

1. Se actualizó `.gitignore` con las entradas faltantes
2. Se ejecutó `git rm --cached` sobre los archivos ya trackeados para desindexarlos
3. Los archivos locales **no fueron eliminados** del disco — solo del índice de git
4. En commits futuros, git ignorará automáticamente esos paths

## Archivos Afectados

| Archivo | Cambio |
|---------|--------|
| `.gitignore` | Agregadas entradas para `.env`, `flask/app/static/`, `frontend/build/` |
| `.env` | Eliminado del tracking (credenciales Docker Compose) |
| `Backend/.env` | Eliminado del tracking (credenciales DB, JWT, sesión) |
| `frontend/.env` | Eliminado del tracking (variables `REACT_APP_*`) |
| `flask/app/static/` (15 archivos) | Eliminados del tracking (build compilado de React) |

## Notas Técnicas

- El build de React en `flask/app/static/` se regenera con `bash scripts/compilar_frontend.sh` — no necesita estar en git
- Las credenciales de los `.env` siguen disponibles localmente; el equipo debe compartirlas por canal seguro (no por git)
- Se usaron patrones `**/.env` y `**/.env.*` para cubrir subdirectorios futuros
- Cualquier desarrollador que clone el repositorio deberá crear sus propios `.env` a partir de un `.env.example` (pendiente de crear en ticket futuro)
