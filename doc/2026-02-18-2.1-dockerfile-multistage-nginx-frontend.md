# Dockerfile Multi-stage: Nginx + Frontend React

**Fecha:** 2026-02-18
**Issue:** [#6](https://github.com/FrancoSeccaspina/proyectoFinal.io/issues/6) — Fase 2 - Dockerización Multi-stage

## Resumen

Se reescribió el `nginx/Dockerfile` como un build multi-stage que compila el frontend React en una imagen temporal y luego copia el resultado al contenedor Nginx. Esto elimina la necesidad del servicio Flask (`activa-flask`), que solo existía para servir los archivos estáticos de la SPA. Nginx ahora sirve el dashboard directamente desde el filesystem.

## Cambios Principales

- **`nginx/Dockerfile`** reescrito con dos stages: Stage 1 compila React con `node:22-alpine`, Stage 2 construye la imagen final de Nginx con el build copiado y Certbot instalado.
- **`nginx/conf.d/base.conf`** actualizado: el bloque `dashboard.activafitness.com.ar` reemplaza el `proxy_pass` a Flask por `try_files` con `root` apuntando a `/usr/share/nginx/html/dashboard`.
- **`docker-compose.yml`** actualizado: el contexto de build de `activa-nginx` pasa de `./nginx` a `.` (raíz del proyecto) para que el Dockerfile pueda acceder a `frontend/`. El volumen `conf.d` se elimina (la conf se copia en la imagen). El servicio `activa-flask` se comenta.

## Flujo de Trabajo

```
[frontend/] ──► node:22-alpine (npm ci + npm run build) ──► /app/build
                                                                 │
                                                                 ▼
                                              nginx:1.21.6 ◄── COPY --from=frontend-build
                                                 │
                                    + Certbot instalado
                                    + base.conf copiada
                                                 │
                                                 ▼
                              /usr/share/nginx/html/dashboard  ◄── SPA servida directamente
```

1. **Stage 1 (frontend-build):** A partir de `node:22-alpine`, se instalan dependencias con `npm ci` y se compila la SPA con `CI=false npm run build`. El resultado queda en `/app/build`.
2. **Stage 2 (imagen final):** A partir de `nginx:1.21.6`, se copia el build de la etapa anterior a `/usr/share/nginx/html/dashboard`, se instala Certbot y se copia `base.conf` como configuración de Nginx.
3. **Nginx resuelve la SPA:** Cualquier ruta del dashboard se resuelve con `try_files $uri $uri/ /index.html`, permitiendo que React Router maneje la navegación del lado del cliente.

## Archivos Afectados

| Archivo | Cambio |
|---------|--------|
| `nginx/Dockerfile` | Reescrito con build multi-stage (node + nginx) |
| `nginx/conf.d/base.conf` | Bloque dashboard: proxy_pass → root + try_files |
| `docker-compose.yml` | Contexto de build = `.`, flask comentado, volumen conf.d eliminado |

## Notas Técnicas

- **`CI=false`** en el build de React evita que las advertencias de ESLint corten el build en entornos CI estrictos (react-scripts trata warnings como errores cuando `CI=true`).
- El contexto de build del servicio `activa-nginx` es ahora la **raíz del proyecto** (`context: .`). Esto es necesario para que el Dockerfile pueda hacer `COPY frontend/` en el Stage 1.
- El volumen `./nginx/conf.d:/etc/nginx/conf.d` se eliminó de docker-compose: la configuración ahora está **bakeada** en la imagen mediante `COPY nginx/conf.d/base.conf /etc/nginx/conf.d/default.conf`. Para modificarla en producción se requiere reconstruir la imagen.
- El servicio `activa-flask` queda **comentado** (no eliminado) para preservar el historial de configuración y facilitar un eventual rollback.
- Las variables `REACT_APP_*` del frontend se leen desde `frontend/.env` al momento del build, ya que el archivo es copiado junto con el resto del directorio `frontend/`.
