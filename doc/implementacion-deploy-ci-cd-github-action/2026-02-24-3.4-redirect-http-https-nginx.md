# Redirect HTTP a HTTPS en Nginx

**Fecha:** 2026-02-24
**Issue:** [#13 — [3.4] Configurar redirect HTTP a HTTPS en Nginx](https://github.com/FrancoSeccaspina/proyectoFinal.io/issues/13)

## Resumen

Se refactorizó la configuración de Nginx para separar los bloques HTTP y HTTPS en bloques `server` independientes. Anteriormente, cada dominio escuchaba en los puertos 80 y 443 dentro del mismo bloque sin forzar HTTPS. Ahora un único bloque HTTP centralizado redirige todo el tráfico al esquema seguro mediante un código 301.

## Cambios Principales

- Eliminados los `listen 80` de los bloques HTTPS de cada dominio
- Agregado un bloque `server` dedicado en puerto 80 que cubre ambos dominios y emite `return 301`
- Los dos bloques `server` restantes quedan exclusivamente en puerto 443

## Flujo de Trabajo

```
Browser: http://activafitness.com.ar/ruta
  │
  └─ Nginx puerto 80 (bloque redirect)
       └─ return 301 https://activafitness.com.ar/ruta
            │
            └─ Nginx puerto 443 (bloque HTTPS - web pública)
                 └─ proxy_pass → activa-backend:3032

Browser: http://dashboard.activafitness.com.ar/ruta
  │
  └─ Nginx puerto 80 (bloque redirect)
       └─ return 301 https://dashboard.activafitness.com.ar/ruta
            │
            └─ Nginx puerto 443 (bloque HTTPS - dashboard)
                 └─ try_files → /usr/share/nginx/html/dashboard
```

## Archivos Afectados

| Archivo | Cambio |
|---------|--------|
| `nginx/conf.d/base.conf` | Refactorización en 3 bloques `server`: redirect HTTP, HTTPS web pública, HTTPS dashboard |

## Notas Técnicas

- `$host` contiene el header `Host` del request (el dominio que pidió el browser).
- `$request_uri` contiene el path completo y query string originales, preservando la URL destino tras el redirect.
- El código `301` indica redirect permanente; los browsers y motores de búsqueda actualizarán sus registros para apuntar directo a HTTPS.
- En desarrollo local el bloque de redirect no se activa si se accede por `localhost`, ya que el header `Host` no coincide con ninguno de los `server_name` configurados.
