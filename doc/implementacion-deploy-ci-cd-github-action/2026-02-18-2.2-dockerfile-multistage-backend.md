# Dockerfile Multi-stage — Backend Express/TypeScript

**Fecha:** 2026-02-18

## Resumen

Reescritura del `Backend/Dockerfile` usando un build multi-stage para separar la compilación de TypeScript de la imagen final de producción. El objetivo es eliminar devDependencies y herramientas de build de la imagen que se despliega, reduciendo su tamaño aproximadamente un 50%.

## Cambios Principales

- `Backend/Dockerfile` reescrito con dos stages (`build` y producción)
- Se reemplaza `npm install` por `npm ci` en el stage de build (instalación reproducible)
- El stage final instala solo dependencias de producción con `npm ci --omit=dev`
- Se elimina el `COPY source/views` redundante del stage final (el build ya los incluye en `dist/`)
- Se agrega `EXPOSE 3032` explícito en la imagen de producción

## Flujo de Trabajo

```
[Source TS + views + public]
        ↓
  Stage 1 (build)
  node:22-alpine AS build
  npm ci  →  tsc + cpx (views, public → dist/)
        ↓
  /app/dist/ (JS compilado + vistas + assets)
        ↓
  Stage 2 (producción)
  node:22-alpine
  npm ci --omit=dev  →  solo deps de producción
  COPY --from=build /app/dist ./dist
  COPY public ./public      ← path absoluto /app/public en app.ts
  COPY uploads ./uploads    ← path relativo en express.static('uploads')
        ↓
  Imagen final sin TypeScript, sin devDependencies
```

**Punto de entrada:** `Backend/Dockerfile`

**Stage 1 — compilación:**
1. Se copia `package*.json` y `tsconfig.json`
2. `npm ci` instala todas las dependencias (incluyendo devDeps: TypeScript, cpx, nodemon)
3. Se copia `source/` con el código TypeScript
4. `npm run build` ejecuta `tsc` y luego `cpx` para mover vistas y assets a `dist/`

**Stage 2 — producción:**
1. Se copia solo `package*.json`
2. `npm ci --omit=dev` instala únicamente dependencias de producción
3. Se copia `dist/` del stage anterior (contiene JS compilado, `dist/source/views/` y `dist/public/`)
4. Se copia `public/` para satisfacer el path absoluto `/app/public` hardcodeado en `app.ts` (línea 100)
5. Se copia `uploads/` para el handler `express.static('uploads')` relativo al cwd (línea 141)

## Notas Técnicas

- **Por qué se copia `public/` en el stage final:** `app.ts` registra dos handlers estáticos para archivos públicos. Uno resuelve via `__dirname` (cubierto por `dist/`), el otro usa `path.join('/app', 'public')` — un path absoluto hardcodeado que requiere que `public/` exista en el WORKDIR de la imagen final.

- **Por qué NO se copia `source/views/` en el stage final:** El script `npm run build` usa `cpx` para copiar las vistas EJS a `dist/source/views/`. Express las encuentra via `path.join(__dirname, 'views')` donde `__dirname` de `dist/source/app.js` es `dist/source/`. Ya están cubiertas por el `COPY --from=build /app/dist`.

- **`npm ci` en lugar de `npm install`:** Garantiza instalaciones reproducibles usando exactamente las versiones de `package-lock.json`, evitando actualizaciones implícitas.

- **`uploads/` en runtime:** En un entorno productivo maduro, este directorio debería montarse como un volumen Docker para persistir archivos entre reinicios del contenedor (ver Ticket 3.x del plan de deploy).
