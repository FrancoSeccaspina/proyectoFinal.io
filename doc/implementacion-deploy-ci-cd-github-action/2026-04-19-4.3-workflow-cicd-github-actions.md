# Workflow real de CI/CD en GitHub Actions

**Fecha:** 2026-04-19
**Ticket:** [4.3] — Crear workflow de CI/CD en GitHub Actions
**Issue:** [#16](https://github.com/FrancoSeccaspina/proyectoFinal.io/issues/16)

## Resumen

Se reescribió el workflow `.github/workflows/deploy.yml`, que era un stub de prueba sin funcionalidad real, por un workflow completo de Build & Deploy. A partir de ahora, cada push a `main` construye automáticamente las imágenes Docker, las publica en GitHub Container Registry (GHCR) y despliega al servidor de producción vía SSH.

## Cambios Principales

- Reescritura completa de `.github/workflows/deploy.yml`
- Dos jobs encadenados: `build-and-push` → `deploy` (el segundo solo corre si el primero fue exitoso)
- Build y push de `activa-backend` desde `./Backend` con Dockerfile multi-stage
- Build y push de `activa-nginx` desde la raíz con `./nginx/Dockerfile` (incluye compilación de React)
- Cada imagen se publica con doble tag: `:latest` y `:<sha-del-commit>`
- Deploy al servidor vía SSH usando `appleboy/ssh-action@v1` con puerto no estándar (`SERVER_SSH_PORT`)
- Ruta del proyecto en el servidor establecida: `/root/proyectoFinal.io`

## Flujo de Trabajo

```
Push a main
    │
    ▼
[build-and-push] — corre en runner ubuntu-latest de GitHub
    ├── Checkout del código
    ├── Login a ghcr.io con secrets.GITHUB_TOKEN
    ├── Build + Push → ghcr.io/francoseccaspina/activa-backend:latest + :<sha>
    └── Build + Push → ghcr.io/francoseccaspina/activa-nginx:latest + :<sha>
    │
    ▼ (solo si exitoso)
[deploy] — corre en runner ubuntu-latest de GitHub
    └── SSH al servidor → cd /root/proyectoFinal.io
                       → docker compose -f docker-compose.prod.yml pull
                       → docker compose -f docker-compose.prod.yml up -d
                       → docker image prune -f
```

**Punto de entrada:** Push a `main` o disparo manual via `workflow_dispatch`

**Resultado:** Los contenedores en producción se actualizan con la nueva versión en ~5 minutos sin intervención manual.

## Notas Técnicas

- El namespace de GHCR se resuelve dinámicamente con `github.repository_owner` → `FrancoSeccaspina`
- Las imágenes que usa el servidor están definidas en `docker-compose.prod.yml` (Ticket 4.2)
- **Secretos requeridos en GitHub** (Settings > Secrets and variables > Actions):

| Secreto | Descripción |
|---------|-------------|
| `SERVER_HOST` | IP del servidor de producción |
| `SERVER_USER` | Usuario SSH del servidor |
| `SERVER_SSH_KEY` | Clave privada SSH dedicada al CI/CD (`activa_deploy`) |
| `SERVER_SSH_PORT` | Puerto SSH no estándar del servidor |

- Si el job `build-and-push` falla, el job `deploy` no se ejecuta (garantía de no romper producción con código que no compila)
- `docker image prune -f` al final de cada deploy libera espacio de imágenes anteriores en el servidor
