# [3.2] Optimizar cron job de devolución de stock

**Fecha:** 2026-02-23

## Resumen

Se optimizó el cron job de devolución de stock para que utilice la variable de entorno `TIEMPO_CONTROL_STOCK_MINUTOS` como intervalo de ejecución, en lugar de correr cada minuto de forma fija. Esto reduce la carga sobre la base de datos y permite ajustar el intervalo sin modificar código.

## Cambios Principales

- Reemplazado el intervalo fijo `* * * * *` (cada minuto) por una expresión cron dinámica construida desde `TIEMPO_CONTROL_STOCK_MINUTOS`
- Agregado fallback a 5 minutos si la variable de entorno es inválida o no está definida
- Importado `IS_PRODUCTION` desde `configEnv` para controlar los logs
- Agregado log de inicio (una sola vez al arrancar) indicando el intervalo configurado
- Agregado log de ejecución condicional: solo se emite si `NODE_ENV !== 'production'`, evitando saturar los logs del contenedor

## Flujo de Trabajo

- **Punto de entrada:** Al iniciar el backend, el módulo carga `TIEMPO_CONTROL_STOCK_MINUTOS` desde las variables de entorno
- **Proceso:** Se parsea el valor a entero; si es inválido o menor a 1, se usa `5` como fallback. Se construye la expresión cron `*/N * * * *`
- **Resultado:** El cron queda programado con el intervalo correcto. En cada ejecución llama a `devolverStockReservasVencidas()`, que busca reservas vencidas, devuelve el stock a los productos y marca las reservas como `EXPIRADO`

```
[Arranque del backend]
  → Leer TIEMPO_CONTROL_STOCK_MINUTOS (env)
  → Parsear a entero / aplicar fallback (5 min)
  → Construir expresión cron */N * * * *
  → Log de inicio: "[cron] Devolución de stock configurada cada N minutos"
  → Programar cron.schedule(expresión)
      → [Cada N minutos]
          → Log de ejecución (solo si !IS_PRODUCTION)
          → devolverStockReservasVencidas()
              → Buscar Reservas {estado: PENDIENTE, vencimiento < now}
              → Por cada reserva: incrementar stock de productos
              → Actualizar estado a EXPIRADO
              → Commit transacción
```

## Notas Técnicas

- **Variable de entorno:** `TIEMPO_CONTROL_STOCK_MINUTOS` (entero, minutos). Valor recomendado: `30`. Ya definida en `Backend/.env.example` y validada al inicio por `validarVariablesDeEntorno()`
- **Fallback:** Si el valor es `NaN` o `< 1`, el cron usa 5 minutos para garantizar operación mínima
- **Logs en producción:** Solo se emite el mensaje de inicio; los logs de cada ciclo se suprimen para no saturar el contenedor
- **Logs en desarrollo:** Se emite un mensaje en cada ejecución para facilitar el debugging local
